# 华容道状态空间分析器

> 把华容道的**状态空间**当成一个数学对象来研究：生成它、测它的拓扑、看它的谱、给它做社区划分、用图神经网络学它的嵌入。

一个 Windows 桌面应用（Tkinter + matplotlib），围绕滑块类谜题的状态图做**代数拓扑 / 拓扑数据分析 / 图机器学习**实验。

---

## 它到底在算什么

以 5×4 棋盘、4 个方块的布局为例，合法状态有 **4.6 万个**；换成 5 个方块就是 **15.4 万个**。
这个巨大的状态图（节点 = 棋盘状态，边 = 一次合法移动）就是本工具的分析对象：

| 分析 | 内容 |
|---|---|
| **状态空间生成** | 从任意初始布局 BFS 出完整状态图；支持"对称性模式"开关（按方块 ID 区分 vs 物理等价合并，后者状态数显著更少） |
| **代数拓扑** | Betti 数 β₀/β₁、Euler 示性数 χ、围长、圈空间维数（单圈/树/森林判定） |
| **谱图分析** | 拉普拉斯与邻接谱、谱半径、代数连通度 λ₂、有效电阻、谱能量 |
| **持久同调（TDA）** | Vietoris–Rips 复形上的 H₀/H₁ 持久条码、持久熵、条码统计，配持久图像（persistence image） |
| **社区检测** | Louvain / greedy modularity，以及 GNN 嵌入 + KMeans 的加速路径 |
| **图机器学习** | 两层 GraphSAGE（链接预测无监督训练）学节点嵌入；TDA 自编码器；sklearn 图级特征；嵌入的 t-SNE/PCA 降维 |
| **可视化** | 3D 状态空间（按 BFS 深度着色、支持旋转/缩放/悬停查看状态）、谱分布、持久条码、AI 综合增强图 |

几个技术点值得单独一提：

- **λ₂ 的求解做了校验 + ARPACK 回退**。直接用 `eigsh(which='SA')` 在病态图上会给出偏小的错值，而 shift-invert 在 n≥20000 时慢到不可用（实测 n=46000 超过 600 秒未完成，ARPACK 方案约 21 秒）。工程里两条路都留着并互相校验。
- **持久同调是自己实现的列约简**，未依赖 gudhi/ripser。Rips 复形的 H₀/H₁ 条数与标准实现在 C4/C6/C8/K6/Q3 五个有解析答案的图上**逐项一致**（回归测试覆盖）。
- **社区检测绕开了 networkx 的一个坑**：`greedy_modularity_communities` 内部的 `_HeapElement.__lt__` 在优先级相同时会退化为比较元素本身，而本工程的节点是 `State`（无 `__lt__`），且 delta-Q 平局极常见 —— 于是这个算法在本工程里**从未成功执行过**，异常被吞后一直返回 `(1 个社区, Q=0)`。现在改为在整数标签的同构副本上跑再映射回原节点。

## 快速开始

### 方式一：直接用打包版（推荐给只想用的人）

到 **[Releases](../../releases/latest)** 下载 `HuaRongDao-v1.0.0-win64.zip`（约 230 MB），
解压后双击 `华容道.exe`。

- 不需要装 Python、不需要联网、不需要装 VC++ 运行库（已随包附带，app-local）
- 首次启动约 10~20 秒（要解包并预热 torch），内存占用约 330 MB
- **整个文件夹一起拷走**才能运行（`_internal\` 必须存在，约 535 MB），别只拷 exe

### 方式二：从源码运行

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install numpy scipy networkx scikit-learn matplotlib torch
python 主程序.py
```

要求 **Python 3.11+**（工程用了 `X | None` 这类写法）。依赖实测版本：

| 库 | 版本 | 用途 |
|---|---|---|
| `numpy` | 1.26.4 | 数值数组 |
| `scipy` | 1.17.1 | 稀疏矩阵、ARPACK 特征分解、最短路 |
| `networkx` | 3.6.1 | 图结构、社区检测、最短路 |
| `scikit-learn` | 1.9.0 | KMeans / PCA / t-SNE / 随机森林 |
| `matplotlib` | 3.6.3 | 嵌入 Tk 的画布与绘图 |
| `torch` | 2.13.0+cpu | GraphSAGE、TDA 自编码器 |
| `tkinter` | 随 Python | 界面（Windows 官方安装包自带） |

> `torch` 用 CPU 版即可，工程对它的使用只到 `torch.nn` / `optim` / 稀疏矩阵乘。

## 界面与用法

左侧五个页签，中间是可视化区（四个视图：3D 状态图 / 谱分布 / 持久条形码 / AI增强图，也可用 **F1~F4** 切换），右侧是分析结果文本框。

典型流程：

1. **绘制**页画一个棋盘（左键创建/扩展方块，右键删除），或「加载文件」读入 `.py`/`.json` 布局
2. 点「生成状态空间」—— 大布局要等几分钟（状态数越多越慢），可随时「停止生成」
3. 点「全拓扑分析」—— 依次跑代数拓扑、谱图、持久同调、社区检测、AI 特征聚类、GNN 嵌入、TDA 深度学习
4. 按 **F4** 看 AI 综合增强图
5. 结果自动存进**缓存**页；同一个棋盘第二次分析是秒级命中

「训练」页可以批量生成随机布局训练 AI（CPU 占用上限可调，默认 50% 不跑满），「模型」页管理多个互不干扰的模型库。


## 关于训练数据

仓库里带的是**三个全局模型**（`gnn_global.pt` / `tda_ae_global.pt` / `ml_global.pkl`，合计约 95 KB），
别人克隆后可以直接用 AI 分析，不用先自己训一遍。

**没有**包含布局级存档（`graph_<hash>.pkl`，单个最大 100 MB）—— 它们是"用户自己算过的那个棋盘"的
缓存产物，只对摆出完全同一个棋盘有意义，换台机器基本读不到，而且重新生成即可。程序会在首次分析时
自动写回 `训练数据\模型\` 与 `训练数据\布局缓存\`。

## 已知边界

- **规模与耗时**：状态数随方块数急剧增长。5×4 / 4 块约 4.6 万节点（端到端全分析约 21 秒），5 块约
  15.4 万节点（约 55 秒）；再大就要几分钟到几十分钟，界面上只有进度文本。
- **RL 求解器已被移除**，不是没做完：它当年的评测指标是伪信号 —— 目标判定只看"存在任意 2×2 方块位于
  底部中央"，不区分方块也不参考初始布局，起点就可能已满足，`solve()` 会直接返回长度为 1 的"解"；
  而 7 万节点的图用数百 episodes 的表格型 Q-learning 也根本无法收敛。相关代码与指标已整体删除。
- **「路径搜索」与「双棋盘寻路」**也按需求移除了。
- **持久同调只支持 H₀/H₁**（Rips 复形只枚举到三角形），传更高 `max_dim` 会明确报错而不是返回空结果。
- **仅 Windows**：打包脚本、VC++ 运行时处理、`.bat` 启动器都是 Windows 专用的；源码理论可跨平台，
  但没有在 Linux/macOS 上验证过。
